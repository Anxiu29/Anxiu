# 改键页面上下布局说明

## 本次为什么先撤回旧改动

从“固定保留 6×21 空槽”开始的几轮修改，把协议矩阵、空槽规则、产品图片推测和页面视觉位置混合在了一起，并继续增加 `present`、矩阵解析器和多版 C98 坐标规则。用户已经明确这些规则不是当前目标，因此本次先完整撤回相关四次提交，恢复到保存事务和会话生命周期优化后的稳定版本，再根据新的界面参考图重新实现。

撤回不删除 Git 历史，而是通过新的反向变更保留修改记录，方便以后追踪为什么放弃这些方案。

## 页面为什么改为上下结构

参考图的核心交互是两块独立区域：

```text
上方：当前设备键位矩阵
      用户先选择需要修改的物理按键

下方：可分配功能矩阵
      用户再选择要写入的新键码
```

旧页面把功能列表放在右侧，横向空间较窄，只能显示两列文字按钮，也不容易通过键盘位置快速找到功能。现在 `App.vue` 使用 `editor-stack` 垂直排列 `KeyboardCanvas` 和 `KeyPicker`，下方选择器可以使用完整页面宽度。

## 下方键盘矩阵如何工作

`KeyPicker.vue` 内的 `keyboardRows` 只描述标准键盘选择器的视觉排列，不代表 C98 设备矩阵，也不参与协议读写。每个按钮仍然使用 `KeyCatalog` 提供的真实键码和名称，点击后通过 `select(code)` 事件交给应用会话更新当前选中的物理键。

选择器分为两种模式：

- **键盘按键**：按照标准键盘的功能区、主键区、导航区、方向键和数字区排列，宽键使用不同宽度。
- **扩展按键**：显示未放入标准矩阵的媒体键、厂商功能键、鼠标键和灯光键等，避免为了模仿界面而丢失已有键码能力。

搜索时，矩阵不会重新排版。匹配项保持正常亮度，不匹配项降低透明度，因此按键位置不会因为搜索而跳动。

### 矩阵距离规则

所有选择器行使用同一个左侧基线，不再分别居中。普通键之间使用统一的 6px 水平和垂直间距；功能键分组、主键区与导航区、导航区与数字区之间使用显式 spacer。宽键的实际宽度按“多个标准键宽度 + 被合并的内部间距”计算，例如 2U 键不是简单的两倍内容宽度，而是 `2 × unit + 1 × gap`。这样每一行的列和分区才能稳定对齐。

## CONNECTED DEVICE 图片

设备摘要左侧不再显示字符图标，而是显示 C98 产品缩略图。点击缩略图会打开遮罩大图，可以通过以下方式关闭：

- 点击遮罩空白区域；
- 点击右上角关闭按钮；
- 按键盘 `Escape`。

原始产品图约 17 MB，不适合直接作为网页资源。项目生成了 `src/assets/c98-keyboard.webp`，在保持清晰查看效果的同时约为 50 KB，由 Vite 使用内容哈希打包。原始图片仍保留在 `doc/` 中作为设计依据。
